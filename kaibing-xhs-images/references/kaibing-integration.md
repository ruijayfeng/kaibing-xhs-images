# 凯冰集成规则

本文件负责 IP 与图文流程的连接。原有风格与布局资源继续负责整页设计；本项目的用户选择优先于原版推荐。

## 角色与实际参考

涉及人物时，读取原始 [ip-core.md](kevinbee/ip-core.md) 与 [character-model.md](kevinbee/character-model.md)，核对 [原始资产索引](kevinbee/source-manifest.yaml)。这些快照保持原文。原始文档中的标准封面默认值、横版画幅、少字规则不接管本 Skill 的整张图文卡片；用户已明确选择封面与内页均用 Q 版、完整卡片 3:4。

当前附带且可直接使用的身份参考，相对于本 Skill 根目录：

`assets/identity/article-q/views/front-three-quarter.png`

它来自原角色仓库，本轮已实际查看。原始 manifest 描述仓库完整库存，未列为本地可用的其他视图不视为已安装。按当前内容设计动作，使用这一参考锁定身份；需要其他角度校准时，先查项目已有资产，仅在确实缺失时只读获取需要的单图。

生成前完成：

1. 解析参考的绝对路径，核实文件存在，用图片查看工具实际查看。
2. 按页决定人物参与方式，再选最少参考；默认一张 Q 版身份图。
3. 共享身份与风格图直接使用项目根目录 Skill 资产的稳定绝对路径，记录来源与 SHA-256；仅对临时或外部输入按需要保存本轮快照，不在月份目录重复复制共享参考。
4. 在图像工具的真实参考参数传入该文件，提示词按图片顺序标明用途。只把路径写在提示词里不算加载。

每张有人物的页都直接加载身份图，包括封面；可追加一张最相关的已确认成品作为风格参考，选择见 [approved-style.md](approved-style.md)。身份图锁定脸、帽星、发色、服装与 Q 比例；风格图锁定配色、字体层级和边距，当前文案决定人物有无、姿势与信息结构。保留 Q 版内部比例，避免混用标准与 Q 全身参考。

## 角色如何进入内容

| 页面 | 默认选择 | 人物任务 |
|---|---|---|
| 封面 | Q 版凯冰 | 与一个可辨主题对象形成动作或选择关系；大标题、人物和对象讲同一件事 |
| 痛点、观点、限制 | 按需要放 Q 版 | 经历、选择、承受或影响本页的核心关系 |
| 操作步骤、机制与验证 | 按内容决定 | 参与理解、尝试、检查或反馈；角色与解释共同构图 |
| 真实截图与结果证据 | 按需要放 Q 版 | 保持关键证据清楚，可在截图外提出问题或指明关注点 |
| 结尾 | 按内容决定 | 参与总结关系或不放人物，避免固定头像模板 |

封面在约 240px 宽缩略图上应能看清主题词、认出帽星与冰蓝发色；使用一个短主标题，副标题只补必要信息。人物身份参考不限定人物位置和姿势。借鉴作者封面时，只借构图、标题体量和人物与对象关系，保留凯冰自己的身份与气质。

为解释型人物场景写一句：去掉凯冰后会失去的理解线索、选择关系或动作张力。若只少了装饰，重新设计或取消人物。作者页脚无需通过这个测试。

移除测试通过后，按[内容表达规则](editorial-content.md)检查事件、接触点及场景语义；人物动作须使正文中的选择、障碍或后果可见，不能仅凭拿纸、看屏幕就视为解释成立。

## 项目视觉偏好

默认 `kaibing-editorial`：借用 minimal 的色彩克制与清楚层级，不继承其单列网格；白色或极浅暖白底、深灰文字，暗红与冰蓝少量强调，角色色彩以实际参考为准。12 种原有风格仍可选择；用户明确选择其他风格时采用该风格，人物身份继续保持。

统一 3:4、边距、字体系统和页脚；封面大标题，内页标题明显小一档。内页按[内容关系构思整页](editorial-content.md#从内容关系构思整页)，再用 balanced、comparison、flow、list、dense 等描述所需密度或关系；这些标签不是固定空间模板。留白用于组织阅读，信息过多先删重复或调整分页。角色与文字共同参与整页构图，避免每页分别堆标题、模块框和插画。

正文完整性、标题与正文尺度、图文分工及密度验收以[内容表达规则](editorial-content.md)为准；不固定字数或正文行数。当前结尾按文章内容设计，不自动追加固定品牌尾页。

只有需要边界时才使用容器或分隔线；默认不使用贴纸、繁复纸纹、荧光渐变或重复 Emoji。每页保留一个主要任务与足够具体的信息。

署名开启时，页脚固定 `凯冰 · NN / TOTAL`，右下对齐，颜色克制、不遮正文；数字来自最终页序。作者文字取自项目 watermark.content，用户关闭署名时同步关闭，不写入其他账号、口号或二维码。

## 文字与尺寸制作

先确定整页的信息结构、文本区域、人物与对象关系，再选择制作方式：

- **整页生成**：用图像工具设计完整卡片，按原文生成中文，使用清楚的无衬线字形；生成字体是模型绘制，不能宣称用了某个真实字体文件。文字有误时修订提示词并重生成。
- **真实字体制作**：文字需确定或证据页需保留真实截图时，用当前可用真实中文字体进行一次整页排版；有新插画时先生成匹配构图的无字母版，无新插画的证据页直接使用原素材。记录实际字体文件、文案与素材位置，避免在已有生成文字上逐块盖补丁。复用当前轻量工具，保持 Skill 的整体设计，不用固定模块网格接管页面。

交付最终 1080×1440。保留工具原图，若尺寸不同，等比缩放到目标画布内并安全填白；不拉伸、裁掉帽星或遮挡正文。若原图比例导致过大空白，先修订构图再生成。生成正文与署名均逐字核对。

## 证据与生成记录

在 outline 的 `Evidence Status` 和生成记录中区分真实截图、官方案例、本轮生成结果、概念示意与待补素材。这些是制作元数据；`Text Content` 只保存读者需要看到的发布文案。插画用图示语言表达，素材分类、审核状态和本轮测试范围留在记录中。正文准确表达来源与个人判断，必要的来源署名仍可保留；真实截图的使用和清晰度限制按[内容表达规则](editorial-content.md)记录，不画仿界面充当实际测试。

读者可能把仿界面、数据或结果误认成实测时，先改成明显的插画，或在正文、配文中自然说明来源与适用条件。确有必要上图的说明列入 `Text Content`，并用 `Reader Disclosure` 记录该句、`Disclosure Reason` 记录它帮助读者判断什么；普通插画不自动追加“概念示意”等角标。实测任务缺少材料仍标待补并阻止交付，不能用去掉标签来掩盖缺失证据。

出图前运行 `python3 scripts/check_publish_copy.py <outline.md>`，检查常见制作标签是否混入发布文案；修改文案后再运行。脚本只检查文字规划，生成后的图片仍须逐字对照文案，确认没有把制作约束印上图。

每次生成保存 `generation-record.json`，包含实际工具名、调用参数、提示词路径、参考绝对路径与角色、来源与摘要、工具返回原图路径、最终文件、尺寸处理、实际字体（如使用）、检查结果和用户审查状态。工具未运行时只记录规划，不编造成功结果。

以当前环境的实际接口为准。当前内置图像工具可接受 `referenced_image_paths`；新图不需要配置额外 API 密钥，但工具权限、额度与返回状态须当次核实。无法传入角色参考时报告具体缺失项并停止人物生成。

## 样张检查

先检查一张样张，再按当前任务授权继续：

- 身份与 Q 比例：白帽红星、冰蓝短发、暗红开衫与参考一致，表情和动作符合角色。
- 内容关系：按[内容表达验收](editorial-content.md#验收完成条件)检查完整回答、图文分工、人物接触点及图中状态是否与正文相符；真实证据保留清楚。
- 阅读：逐字核对中文、英文、署名与页码；检查溢出、对齐和层级；封面约 240px、内页约 360px 宽查看，正文仍可读。
- 整体：封面标题醒目，内页标题不挤占正文，署名克制，人物、物件、文案形成清楚阅读路径。
- 来源：概念示意与实际结果可区分；不把定制凯冰效果描述成原 Skill 内置能力。

结构检查通过仅说明配置可读。视觉质量按[复核与修订](editorial-content.md#复核与修订)实际验收；制作检查与用户认可范围分别记录，存在未解决的质量问题时继续修订。
